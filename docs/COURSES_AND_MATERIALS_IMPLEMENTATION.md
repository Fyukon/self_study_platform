# Этап «Курсы и материалы» — отчёт о реализации

Дата завершения: 14 июля 2026 года
Статус: завершено

## Короткий итог

В приложение добавлен полный вертикальный срез этапа 3 ТЗ:

- SQLite хранит курсы, модули, ресурсы и связи модулей с темами roadmap;
- курс можно создать, изменить и отправить в архив вручную;
- модуль можно создать, изменить, удалить и перевести между статусами;
- к модулю можно прикрепить книгу, видео, репозиторий, статью, ссылку или локальный файл;
- модуль можно связать с одной или несколькими темами roadmap;
- Markdown и JSON импортируются только через обязательный preview;
- backend API, React UI и тесты добавлены в один согласованный контракт;
- архитектурная карта и README обновлены в той же поставке.

## Цели и границы этапа

Цель этапа — дать пользователю место, где внешний учебный материал становится частью личного маршрута: его можно сгруппировать по модулям и привязать к теме, которую нужно освоить.

В этот этап вошли каталогизация и ссылки. В него намеренно не вошли проигрывание видео, чтение Markdown внутри приложения, копирование локальных файлов, журнал учебных сессий, таймер, проекты, аналитика и backup. Эти возможности относятся к следующим этапам ТЗ.

## Модель данных

### `courses`

Хранит название, описание, провайдера, исходную ссылку, порядок и признак архивации. Удаление через API является архивированием, поэтому случайное действие не уничтожает курс и его историю.

### `course_modules`

Принадлежит курсу через foreign key с `ON DELETE CASCADE`. Модуль имеет название, описание, порядок и один из статусов:

- `not_started` — не начат;
- `in_progress` — в процессе;
- `completed` — завершён.

Новые модули запрещено добавлять в архивный курс, но архивный курс остаётся доступен для просмотра и восстановления.

### `resources`

Принадлежит модулю и содержит тип, название, адрес, локальный путь, заметку и порядок. Типы:

`book`, `video`, `repository`, `article`, `link`, `local_file`.

Для удалённых материалов backend принимает только `http://` и `https://`. Для `local_file` принимается только непустой `local_path`, без URL. Это правило продублировано на уровне SQLite CHECK, поэтому некорректную комбинацию нельзя записать обходом HTTP-валидации.

Приложение не читает и не копирует локальный файл: оно сохраняет ссылку на путь пользователя и показывает её как `file://`-адрес.

### `course_module_roadmap_links`

Связывает модуль курса с `roadmap_nodes`. Пара `(module_id, node_id)` уникальна, поэтому повторная связь возвращается как `409 ROADMAP_LINK_EXISTS`. При удалении темы roadmap связь удаляется каскадно.

## API

Все маршруты находятся под `/api/v1`.

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/courses` | Список курсов с количеством модулей и материалов |
| `POST` | `/courses` | Создание курса |
| `GET` | `/courses/{id}` | Курс с модулями, ресурсами и roadmap-связями |
| `PUT` | `/courses/{id}` | Изменение курса или архивационного признака |
| `DELETE` | `/courses/{id}` | Архивирование курса |
| `POST` | `/courses/{id}/modules` | Создание модуля |
| `PUT` | `/course-modules/{id}` | Изменение модуля |
| `DELETE` | `/course-modules/{id}` | Удаление модуля с дочерними данными |
| `POST` | `/course-modules/{id}/resources` | Создание материала |
| `PUT` | `/resources/{id}` | Изменение материала |
| `DELETE` | `/resources/{id}` | Удаление материала |
| `POST` | `/course-modules/{id}/roadmap-links` | Создание связи с темой roadmap |
| `DELETE` | `/course-modules/{id}/roadmap-links/{linkId}` | Удаление связи |
| `POST` | `/courses/import/preview` | Парсинг и валидация Markdown/JSON без записи в БД |
| `POST` | `/courses/import` | Импорт по одноразовому `preview_id` |

Ошибки используют общий формат приложения:

```json
{
  "error": {
    "code": "INVALID_RESOURCE",
    "message": "url is required",
    "details": {}
  }
}
```

## Импорт и обязательный preview

Импорт сделан двухфазным:

```text
текст пользователя
      │
      ▼
POST /courses/import/preview
      │  parse + strict validation
      ▼
preview_id + состав курса + срок действия
      │  пользователь проверяет результат в UI
      ▼
POST /courses/import { preview_id }
      │  one-time consume + transaction
      ▼
курс, модули и материалы в SQLite
```

### Почему preview хранится в памяти

Preview не является учебными данными и не должен оставлять в базе промежуточные записи. Он хранится в памяти процесса, автоматически очищается через 15 минут и удаляется в момент использования. Это даёт три свойства:

1. до подтверждения импорт не меняет SQLite;
2. повторная отправка одного preview не создаёт дубль;
3. старый или неизвестный идентификатор не может записать данные.

Если приложение перезапустить между preview и импортом, preview потребуется построить заново. Это приемлемо для локального single-user приложения и безопаснее, чем незаметно хранить неподтверждённые копии содержимого.

### Markdown

Поддерживается один верхнеуровневый заголовок курса, произвольное описание, заголовки модулей второго уровня и списки материалов:

```markdown
# Go для backend-разработки

Практический курс с книгами и исходниками.

## Основы языка

Типы, функции и работа с ошибками.

- [book] The Go Programming Language — https://example.com/go-book
- [repo] Практические примеры — https://github.com/example/go

## Локальные заметки

- [local] Мой конспект — /home/user/notes/go.md
```

Поддерживаются псевдонимы типов `[repo]`, `[local]`, `[file]`, `[url]`. Если маркер типа не указан, материал считается обычной ссылкой. Для разделения названия и адреса поддерживаются `—`, `|` и ` - `.

### JSON

JSON намеренно декодируется со строгим запретом неизвестных полей. Минимальная структура:

```json
{
  "title": "Go для backend-разработки",
  "description": "Практический курс",
  "provider": "Self study",
  "source_url": "https://example.com/course",
  "modules": [
    {
      "title": "Основы языка",
      "description": "Типы и функции",
      "resources": [
        {
          "title": "Книга",
          "resource_type": "book",
          "url": "https://example.com/book",
          "note": "Главы 1–2"
        }
      ]
    }
  ]
}
```

Импортированный модуль получает статус `not_started`. Roadmap-связи после импорта добавляются вручную: это позволяет проверить, что конкретный материал действительно относится к выбранной теме, а не импортировать неподтверждённые идентификаторы из внешнего файла.

## UI-решения

Новый экран `/courses` состоит из двух зон:

- боковая библиотека с количеством модулей и материалов, кнопкой ручного создания и входом в импорт;
- рабочая область курса с метаданными, модулями, ресурсами, roadmap-связями и статусами.

Форма материала меняет поле адреса в зависимости от типа: для удалённых ресурсов показывается URL, для локального файла — путь. В списке материалов ссылка открывается в новой вкладке, а локальный путь остаётся обычной `file://`-ссылкой без попытки доступа к файловой системе backend-сервером.

Панель импорта показывает до записи:

- название и описание курса;
- число модулей;
- число материалов;
- срок действия preview;
- список модулей и их состав.

Все новые компоненты используют существующие CSS-переменные темы (`--panel`, `--accent`, `--border`, `--muted` и т.д.), поэтому светлая тема сохраняет тёплый книжный характер, а тёмная получает те же структурные состояния.

## Известные ограничения и следующий шаг

На этом этапе намеренно нет:

- статуса прочитанности отдельных ресурсов;
- перетаскивания для изменения порядка курсов, модулей и материалов;
- импорта roadmap-связей из внешнего файла;
- проверки существования локального пути и открытия файла через backend;
- автоматического получения metadata по URL;
- журнала сессий, таймера и учёта фактически затраченного времени.

Следующий логичный этап — сессии и проекты. Он сможет использовать уже созданные course/module/resource и roadmap-связи как контекст учебной сессии, а Dashboard — показывать фактическое время и активность по курсам.
